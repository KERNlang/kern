# KERN 5 RT-8: `integer` as an exact alias of the `number` signature spelling

**Status:** IMPLEMENTED
**Date:** 2026-09-01
**Base:** `55e92de8` (RT-6 merged)
**Tribunals:** choice tribunal and F5 amendment ruling — `integer` is an EXACT ALIAS
of the already-admitted `number` signature spelling, not a new KIR kind.
**Confidence:** 0.93

## Executive Summary

RT-8 is the first **frontend (F5) amendment** slice. Its purpose is to exercise the
F0/F5 amendment protocol on the smallest real change that exists: KERN's KIR has
carried the kind `integer` since the structural constitution was frozen, but the only
source spelling that reached it was `number`. Writing the honest word — `integer` —
was fatal at projection. This slice admits `integer` and `integer[]` as exact
alias spellings of `number` and `number[]`, and adds the amendment machinery the
protocol turned out not to have.

Node and property counts are unchanged (302 / 1,149). No KIR kind, expression kind,
statement kind, diagnostic code, or runtime semantic was added. Every twin lowers to
byte-identical canonical KIR, so both emitters and the RT-1 envelope are unchanged
by construction.

## [RT8-R1 DECIDED] The alias is a spelling, not a kind

`integer` routes to the same `f5typekind(limits, "integer")` path as `number`, and
`integer[]` to the same `f5typelist(limits, "integer")` path as `number[]`. Nothing
downstream can distinguish the two spellings, because nothing downstream ever sees
them: the spelling dies at F5.

Admitted handler-type spellings after this slice: `boolean`, `number`, `integer`,
`string`, and lists of those; plus `void` in return position only. `void` is still
never a parameter or a list element.

## [RT8-R2 DECIDED] The amendment protocol had no writer — headline finding

This is the finding the first amendment slice existed to produce.

`scripts/kern-frontend-f5-projection/policy.json` hash-pins every composition
`.kern`, including `f5-property-projection.kern`. Editing that file invalidates the
pin and the F5 worker fails closed at load with
`F5 projection policy: digest examples/kern-frontend/f5-property-projection.kern`.

Every pin in the F5 and closure surface is **verify-only**. There is no
`writeFileSync` and no `--write` anywhere under `scripts/kern-frontend-f5-projection/`
or `scripts/kern-frontend-closure/`; the pins are authenticated by
`policy-integrity.test.mjs:31-33` and `scripts/kern-frontend-closure/validate.mjs:197-198,234-235,265-266`
and regenerated by nothing. `build-kern-frontend-projection-assets.mjs` is **not** the
regenerator: it exits 0 on a drifted composition file and bundles it, leaving the
runtime to fail closed later. It is a bundler, not a gate.

So before RT-8, the only way to land any edit to a composition `.kern` was to
hand-write a digest — exactly what the protocol forbids.

## [RT8-R3 DECIDED] Amendment-gated re-pinning

`scripts/kern-frontend-closure/amend.mjs` (80 lines) re-pins **only**
`policy.json.composition[*].sha256`, and only under a matching amendment record in
`scripts/kern-frontend-closure/amendments/`. It refuses, non-zero and without
writing, when:

- a composition file drifted and no amendment names it;
- more than one amendment claims the same file;
- the amendment's `parentDigest` is not the digest currently pinned for that file
  (stale or forked amendment);
- the amendment's `parentClosureLedgerSha256` is not the current closure-ledger digest;
- the declared node or property counts differ from the ledger's;
- a declared row carries a disposition the ledger does not hold, or claims more rows
  of a disposition than the ledger holds;
- the amendment is not `additive`;
- it names a pin target other than the F5 policy.

Without `--write` it verifies the chain and reports pending re-pins.

Two properties matter beyond the checklist:

- **Surgical.** The writer substitutes the digest string in the raw policy text after
  proving it occurs exactly once. It never re-serializes the JSON, so it cannot move
  a byte the amendment did not license. The policy file's compact descriptor
  formatting is preserved and the diff is one line.
- **Single use.** Once consumed, the amendment's `parentDigest` no longer equals the
  pinned digest, so the same record cannot re-bless a later edit. Re-blessing
  requires a new amendment naming the new parent.

`policy-integrity.test.mjs` is untouched and remains the second, independent
recompute of the same digest.

## Oracle

`scripts/kern-5-rt8-integer-signatures/`, root script
`test:kern-5-rt8-integer-signatures`. The script rebuilds the projection assets
after the `.kern` edit before the asset-consuming legs run; without that the legs
silently test stale assets.

| Leg | What it pins |
| --- | --- |
| admission | `integer` / `integer[]` project in every position; `Integer`, `INTEGER`, `int`, `Int`, `integers`, `integer[][]`, `decimal`, `json`, `unknown` and their list forms still drift |
| 1 — canonical KIR | integer twin is byte-identical to number twin for parameter, return, both, and list shapes |
| 2/3 — emitters | emitted JavaScript and Python are byte-identical across the twins |
| 4 — RT-1 envelope | envelope byte-identical across the twins on all three execution legs |
| 4b — fractional twin | `1.5` refused identically at an integer-spelled and a number-spelled parameter, on all three legs |
| chain | the amendment protocol's own refusals, idempotence, single use, and surgical diff |

**Legs 2, 3 and 4 are corroborating, not independent.** Because the twins produce
byte-identical KIR, the emitters and the envelope cannot diverge unless the KIR does.
They earn their place by catching KIR-differing mutants (`M04`, `M07`) and stale
assets (`M18`), not by independently discriminating the alias. Leg 1 and the
admission and fractional legs carry the discrimination.

## [RT8-R4 DECIDED] The fractional refusal is opaque

Recorded exactly, byte-identical on direct, JavaScript and Python:

```
{"completion":{"kind":"error"},
 "diagnostics":[{"category":"runtime","code":"invalid-handler-arguments","phase":"link"}],
 "events":[],"format":"kern.runtime.kir.v1","outcome":"failure",
 "requestId":"...","result":{"presence":"absent"}}
```

It does **not** name `expected=integer` or `got=decimal`. The internal message
`argument v has wrong type` (`kir-runtime/execute.ts:74`) is swallowed by the
envelope, which carries only the code and `phase:"link"`. The oracle therefore
asserts the envelope shape and three-leg byte-equality, and additionally asserts
that the envelope leaks none of `expected`, `decimal`, `wrong type`, `1.5`, or
`integer` — so the alias cannot be inferred from a refusal. A naive assertion on a
named expected/got payload would never have passed.

Queued, not done: surfacing a typed argument-refusal diagnostic is a naming-authority
follow-up, not part of this slice.

   `decimal` remains the separate kind. Deprecating `number` is a source-compatibility
   decision and needs its own slice.
2. **Typed refusal.** Surface expected/received type in the argument-refusal
   diagnostic (RT8-R4).

   have no writer; they did not move in this slice, so no writer was needed. The next
